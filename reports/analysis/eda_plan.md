# EDA plan: Home Credit repayment difficulty

## Plan boundary

This document is a plan only. No file was profiled, joined, summarized, or
charted while preparing it. Analyses that use `TARGET` are limited to
`application_train.csv`; `application_test.csv` is used only for the stated
train/test comparability checks. A payment-difficulty association is not a
causal effect, a lending-policy recommendation, or a claim about people who
were not issued a loan.

**Application-time rule.** Start with a field-level availability register
(item 28) before producing any target comparison. A derived feature is eligible
only if every input was known on or before the current application decision.
For historical child tables, validate and enforce relative dates at or before
the application (`MONTHS_BALANCE <= 0`; applicable `DAYS_* <= 0`) and retain
the source timestamp/snapshot rule in the feature definition. Do not use
`TARGET`, post-origination installments, future monthly snapshots, or records
whose as-of timing cannot be demonstrated as inputs.

## Execution gates after plan approval

1. Complete items 1–5 and 33 before any target association.
2. Complete items 8, 28, and 29 before extracting a single historical
   cross-table feature.
3. Treat fairness/proxy items as descriptive governance work. Do not use
   protected attributes (`CODE_GENDER`) as model inputs merely because they
   support an audit.
4. Keep a reproducible data-quality, temporal-filter, and feature-definition
   log alongside every eventual chart/table.
